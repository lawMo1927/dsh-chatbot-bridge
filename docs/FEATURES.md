# 功能清单

本文件登记插件的全部预计功能与验证方式，供核验使用。

## 一、桥接核心（host 插件，index.js）

| 编号 | 功能 | 预期行为 | 验证方式 |
|---|---|---|---|
| A1 | 任务提交 | `POST /task` 传入 prompt 与 umo，返回 taskId，任务进入队列串行执行 | 提交任务后 `GET /task/:id` 状态从 queued 变为 running 再到 completed |
| A2 | 任务状态 | `GET /task/:id` 返回状态、结果摘要、耗时 | 提交后轮询该接口观察状态变化 |
| A3 | 结果回传 | 任务完成后结果进入待发送队列，`GET /reports` 拉取，`POST /reports/ack` 确认 | 完成一次任务后拉取 reports，确认后不再返回 |
| A4 | 进度询问 | `POST /progress` 在任务执行中插入追问 | 长任务执行中调用，观察到追问内容进入会话 |
| A5 | 中断任务 | `POST /task/cancel` 取消当前任务 | 长任务执行中调用，任务状态变为 cancelled |
| A6 | 继续任务 | `POST /task/continue` 对中断或结束的任务继续 | 中断后调用，任务重新进入队列 |
| A7 | 会话列表 | `GET /sessions` 返回父会话列表，含标题、cwd、是否归档 | 调用接口与 DSH 会话列表对照 |
| A8 | 会话操作 | `POST /sessions/operate` 对任意会话提交 prompt 或 cancel | 对空闲会话提交 prompt，观察会话出现新回合 |
| A9 | 会话恢复 | DSH 重启后从 state.json 恢复上次会话 | 重启 DSH 后提交任务，日志出现"恢复历史会话" |
| A10 | 工作区归属 | 创建或恢复会话后自动归入 cwd 匹配的工作区 | 新会话出现在 DSH 侧边栏对应工作区分组 |
| A11 | 审批双通道 | 页面与聊天同时收到审批，任一渠道先答有效；页面未开时落聊天 | 分别测试三条路径：页面应答、QQ 先答、页面未开 |
| A12 | 产物文件 | 工作区内不超过 50MB 的文件随结果发送 | 任务产出文件后检查聊天收到的文件 |
| A13 | 健康检查 | `GET /health` 返回桥接存活 | 直接请求返回 ok |

## 二、进程管理

| 编号 | 功能 | 预期行为 | 验证方式 |
|---|---|---|---|
| B1 | 聊天机器人启停重启 | 通过面板按钮控制 AstrBot 进程 | 点启动后 6185 端口监听，点停止后关闭 |
| B2 | 启动等待状态 | 点启动后按钮显示"正在启动..."，最长等 90 秒 | 点击后观察按钮文案与最终状态 |
| B3 | NapCat 启动 | 直接运行 launcher.bat，检测 6099 端口 | 点击后 NapCat 与 QQ 进程出现，6099 监听 |
| B4 | QQ 登录状态 | 通过 NapCat 接口读取登录状态 | 面板显示已登录或未登录 |
| B5 | 二维码获取 | 未登录时获取二维码链接并生成 PNG 图片 | 面板显示二维码图片，手机可扫 |
| B6 | 状态汇总 | `GET /admin/status` 返回聊天机器人、NapCat、桥接、管理员 QQ、QQ 登录 | 调用接口核对字段 |

## 三、配置与安装

| 编号 | 功能 | 预期行为 | 验证方式 |
|---|---|---|---|
| C1 | 环境检测 | 检测 uv、AstrBot、NapCat、QQ 的安装状态与运行状态 | 面板安装页显示四项状态 |
| C2 | 安装 uv | 执行官方安装脚本 | 缺失时点击安装，完成后状态变为已安装 |
| C3 | 安装 AstrBot | 通过 uv 安装 AstrBot | 缺失时点击安装，完成后路径存在 |
| C4 | 安装 NapCat | 下载 GitHub 发布包并解压到配置目录 | 缺失时点击安装，完成后 launcher 存在 |
| C5 | AstrBot 桥接插件安装 | 把 adapters/astrbot 复制到 AstrBot 插件目录 | 点击后目标目录出现 main.py 与 metadata.yaml |
| C6 | 设置读写 | `GET/POST /admin/settings` 读写管理员 QQ、工作区、聊天机器人目录与启动程序、NapCat 地址与 token | 面板修改后重启 DSH，改动仍在 |
| C7 | 日志读取 | `GET /admin/logs` 返回最近日志 | 面板日志页显示内容 |
| C8 | 人格管理 | 列表、详情、保存、新建 | 面板人格页增改查 |
| C9 | 默认人格模板 | `GET /admin/persona-template` 返回通用模板 | 人格页点"载入默认模板"填入编辑框 |
| C10 | 模型设置 | 读写当前模型与降级列表，返回按供应商归组的可用模型 | 面板模型页切换当前模型后 AstrBot 实时生效 |
| C11 | 供应商配置 | 读写供应商的 API 地址与 Key，支持新增供应商 | 面板模型页修改 Key 后 AstrBot 实时生效 |
| C12 | 提供商管理 | 列表与单个提供商的模型名、Key 更新 | 接口可用 |

## 四、面板界面（client 插件）

| 编号 | 功能 | 预期行为 | 验证方式 |
|---|---|---|---|
| D1 | 侧边栏入口 | 侧边栏出现"聊天机器人"，点击打开管理页 | 页面加载后查看侧边栏 |
| D2 | 进程页 | 基本设置（管理员 QQ、工作区）、启停重启、NapCat 启动、QQ 状态与二维码、桥接状态 | 逐项点击验证 |
| D3 | 安装页 | 环境检测每 2 秒刷新、组件安装按钮、AstrBot 插件安装、说明、高级设置、安装输出 | 逐项验证 |
| D4 | 人格页 | 人格列表、新建人格、编辑保存、载入默认模板、放弃修改 | 逐项验证 |
| D5 | 模型与 API 页 | 当前模型下拉按供应商分组、降级列表带顺位、供应商配置、添加供应商 | 逐项验证 |
| D6 | 日志页 | 显示最近 200 行、手动刷新 | 点击刷新观察内容变化 |

## 五、AstrBot 侧插件（adapters/astrbot）

| 编号 | 功能 | 预期行为 | 验证方式 |
|---|---|---|---|
| E1 | 设置读取 | 启动时从桥接读取管理员 QQ 与工作区 | 启动后 AstrBot 日志出现"已加载设置" |
| E2 | 任务工具 | run_dsh_task 把任务交给 DSH 执行 | QQ 里让机器人执行文件操作，DSH 会话出现对应任务 |
| E3 | 进度与中断 | ask_dsh_progress 查询进度，cancel_dsh_task 中断 | 长任务中调用两个工具 |
| E4 | 文件工具 | send_workspace_file 发文件，read_workspace_file 读文件 | 对工作区内文件调用 |
| E5 | 会话工具 | list_dsh_sessions 列会话，operate_dsh_session 操作会话，continue_dsh_task 继续任务 | 逐项调用 |
| E6 | 审批轮询 | 拉取待审批请求推送给管理员，管理员回复允许或拒绝 | 触发越权操作，QQ 收到审批通知并回复 |
| E7 | 报告轮询 | 拉取结果并发送到聊天，含文件 | 任务完成后 QQ 收到结果 |
| E8 | 系统提示注入 | 每个请求注入 DSH 使用规则 | 检查模型行为符合规则 |
| E9 | 群消息 | 只有管理员在群里的消息被处理 | 非管理员发消息无响应 |

## 七、已知限制

1. QQ 客户端安装器是交互式的，面板只能检测，无法静默安装
2. QQ 扫码登录必须人工完成
3. 审批在 QQ 先答时，DSH 页面上的审批卡片不会自动消失，需要手动忽略
4. 工作区修改只对之后新建的会话生效，已有会话仍用原目录
5. 从零环境的完整安装流程尚未实机全量验证（本机组件此前已装好）
6. 独立 Bridge 形态与插件形态共用 9412 端口，不能同时运行
